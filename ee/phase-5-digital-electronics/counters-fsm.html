Counters and FSMs

Ripple counters chain flip-flops — fast to design, slow to settle. Synchronous counters share a clock — uniform, fast, predictable. State machines extend the idea: a clock advances a register, combinational logic decides the next state.

4-bit binary counter — two implementations

Both count 0→15 on rising clock edges. The ripple counter chains T-flip-flops; each bit triggers the next, so the carry walks across the bits one gate-delay at a time. The synchronous counter clocks all four flip-flops together, with combinational logic deciding which bits toggle next.

Each T-FF clocks on the previous Q output. When Q0→1 toggles after delay τ, Q1 only sees that edge τ later, and so on. At count=7→8, all four bits propagate sequentially over 4·τ — visible as the orange flash walking from Q0 to Q3.

All bits update together one τ after the edge. Carry logic feeds T-inputs: T0=1, T1=Q0, T2=Q0·Q1, T3=Q0·Q1·Q2.

Timing comparison. Ripple counter: each bit's edge is staggered by τ. Synchronous: all bits transition together after one τ. The ripple's worst-case total delay grows linearly with bit-width — limits its max frequency.

Moore FSM — traffic light controller

Three states, three outputs. In a Moore machine the output depends only on the current state (not the input) — so the lights are stable as long as the state holds. The clock advances Red→Green→Yellow→Red.

Encoded with 2 bits (state register Q1Q0): RED=00, GREEN=01, YELLOW=10. Next-state logic is combinational; output logic is just decoded state — Moore.

74HC595 — serial-in, parallel-out (SIPO)

Eight cascaded D-flip-flops. SER feeds Q0 on each SRCLK edge; everything shifts left. RCLK transfers the shift register into the output latch — the visible LEDs only update when you pulse RCLK. This is how the GPIO expansion trick works.

What to notice

  • Ripple delay grows linearly with bit-width — a 16-bit ripple counter has 16·τ worst case. Above ~50 MHz, only synchronous counters are usable.
  • Synchronous counters need carry logic — T0=1, T1=Q0, T2=Q0·Q1, etc. More gates, but every bit settles in one τ.
  • Moore output depends only on state — outputs are glitch-free as long as the state register is glitch-free. Mealy is faster (no extra clock cycle) but outputs can glitch on input changes.
  • State encoding choices — binary (log2 N FFs), one-hot (N FFs, simpler decode), Gray (one bit changes per transition, useful for clock-domain crossing).
  • 74HC595 separates shift from latch — you can update the shift register at SPI speeds without flicker; only RCLK reveals the new pattern.

ENCODINGS

  • Binary — fewest FFs (⌈log₂ S⌉), more decode logic.
  • One-hot — 1 FF per state; preferred in FPGAs (fast, simple decode).
  • Gray — adjacent states differ by 1 bit; useful across clock domains.
  • Moore = safe, Mealy = fewer states but glitch-prone.

COMMON PITFALLS

  • Mealy output glitches — outputs change with input during a state; register them.
  • Ripple counter skew — bits update at different times; never use ripple outputs as clock or for parallel sampling.
  • Missing reset — unreached states stuck on power-up; always define reset behavior.
  • Async reset deassertion — must be synchronous to clock to avoid recovery violations.
