Flip-Flops and Latches

Latches are level-sensitive; flip-flops are edge-triggered. Toggle inputs, drive the clock, and watch setup/hold violations cause metastability.

Memory in digital logic is a feedback loop — an output fed back to an input. The cells below all use that trick: cross-coupled gates (SR latch), or a master/slave pair gated by a clock edge (D flip-flop). The setup and hold windows around the clock edge are where most real-world bugs hide; a brief animation at the end shows what happens when D wiggles inside that window.

NAND SR latch — active-low inputs

Two cross-coupled NANDs. Inputs are S̄ and R̄ (active low). With S̄=R̄=1 the latch holds. S̄=0 sets Q=1. R̄=0 resets Q=0. S̄=R̄=0 forces both outputs HIGH — illegal because the state is undefined when both go HIGH together.

D flip-flop — edge triggered

Q captures D on the rising edge of CLK. Between edges, D can change freely and Q ignores it. Setup time (tsu) is how long D must be stable before the edge; hold time (th) is after. Click the clock or auto-run.

Yellow shaded bands = tsu (before edge) and th (after edge). Q updates only at the rising edge marker. If D changes inside a band, the visualizer flags a setup/hold violation.

JK flip-flop

Set when J=1,K=0. Reset when J=0,K=1. Hold when J=K=0. Toggle when J=K=1 — no forbidden state (the bug the SR latch had).

T flip-flop — toggle

T=1 means "toggle on each clock"; T=0 means hold. T flip-flops are the building blocks of ripple counters: Q outputs of a chain of T-FFs with T tied HIGH form a binary counter.

Metastability — D changes during setup/hold window

If D transitions inside the setup or hold band, the master latch can't decide. Q may sit between rails for an indeterminate time, or take a random valid value. In real silicon this can briefly violate logic levels and propagate corrupted state. Standard cure: synchronizer — two flip-flops in series with the second's output trusted.

Purple = Q in a metastable region (between rails). After a recovery time, it resolves to a random valid level. Use a two-FF synchronizer for any asynchronous input crossing a clock domain.

What to notice

  • Latch = level-sensitive, flip-flop = edge-sensitive. A D-latch passes D through whenever enable is HIGH; a D-FF captures D once per edge. The distinction is everything for pipelined design.
  • The forbidden SR state isn't "broken" until the inputs release — both outputs sit at 1; when S̄ and R̄ both return to 1, whichever NAND switches first wins, which is a race.
  • Setup/hold windows are vendor specs — typical 74HC74: tsu=20 ns, th=3 ns at 5 V (TI SN74HC74 datasheet). CMOS at 3.3 V: a few ns. FPGA fabric flip-flops: sub-nanosecond.
  • JK eliminates the forbidden state by making J=K=1 mean "toggle." That is also why JK is the natural building block for synchronous counters.
  • Metastability is unavoidable for true async inputs — you can only reduce the probability by adding synchronizer stages. The MTBF improves exponentially with each added FF.

MEMORIZE

  • SR latch (NAND) — S̄=R̄=0 forbidden → both Q=Q̄=1.
  • D flip-flop — Q follows D on clock edge; the default storage cell.
  • Synchronizer — 2 FFs in series before any combinational logic for async inputs.

COMMON PITFALLS

  • Async signals into clocked FF — guaranteed metastability without a synchronizer.
  • Setup/hold violation — D wiggling near the edge → undefined Q for ps to ns.
  • Latch inferred accidentally — incomplete if in HDL creates a latch; always use else.
  • Clock skew — different arrival times can convert setup margin into a hold violation.
