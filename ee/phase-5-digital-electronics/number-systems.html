Number Systems

Toggle bits to see the same value in binary, decimal (unsigned and two's-complement signed), and hex. Side panel walks through invert-and-add-one and byte-order.

Every numeric value in a register, memory cell, or wire-protocol packet is a string of bits. The same bits mean different things depending on whether the program treats them as unsigned, signed (two's complement), or a hex-coded flag field. The conversions below — and the LSB / MSB labeling — let you read a register dump without reaching for a calculator.

Positional notation

Each bit's place value is 2 raised to its position. The unsigned decimal is the sum of place values where the bit is 1.

Two's complement — how negative numbers work

To negate a value: invert every bit, then add 1. The MSB acts as the sign (1 = negative). This makes A − B equal to A + (−B), so the hardware adder works for both signed and unsigned.

Step 1 — current value
0000 0101 (+5)
Step 2 — invert all bits (one's complement)
1111 1010
Step 3 — add 1
1111 1011 (−5)
Check: original + negated
+5 + (−5) = 0 (with carry out)

Byte order — little-endian vs. big-endian

A 32-bit value 0x12345678 stored at memory address 0x1000:

Little-endian (x86, ARM default, AVR, RP2040): LSB at lowest address
0x78@ 0x1000
0x56@ 0x1001
0x34@ 0x1002
0x12@ 0x1003
Big-endian (network byte order, older PowerPC/SPARC): MSB at lowest address
0x12@ 0x1000
0x34@ 0x1001
0x56@ 0x1002
0x78@ 0x1003

What to notice

  • Hex is just 4-bit shorthand — every hex digit maps to exactly 4 binary bits. A byte = 2 hex digits, 16 bits = 4 hex digits. That's why register dumps are in hex.
  • MSB tells you the sign — in two's complement, MSB=0 means non-negative, MSB=1 means negative. Same bits, different interpretation.
  • 0xFF is −1 signed but 255 unsigned — toggle every bit on. Whether it means "all flags set," "−1," or "255" is the programmer's call.
  • Range is asymmetric — 8-bit signed goes -128 to +127, not -127 to +127. There's one more negative value because 0 takes a slot on the positive side.
  • Little-endian feels backwards in a hex dump — but it lets the CPU read a byte, word, or dword from the same address without changing the starting offset. That's the engineering trade.

Worked example — reading an MPU6050 accelerometer X-axis register pair

The hardware

MPU6050 (InvenSense IMU): X-axis acceleration is stored as a signed 16-bit integer split across two 8-bit registers: ACCEL_XOUT_H (0x3B) holds bits [15:8], ACCEL_XOUT_L (0x3C) holds bits [7:0]. Default range = ±2 g, so each LSB = 2 g / 32,768 = 61 µg.

Raw I²C read

ACCEL_XOUT_H (0x3B) = 0xF8
ACCEL_XOUT_L (0x3C) = 0x40

Step 1: Assemble (big-endian — MPU6050 is high-byte-first)

raw = (0xF8 << 8) | 0x40 = 0xF840 = 1111 1000 0100 0000₂ = 63,552 unsigned

Step 2: Interpret as signed int16 (MSB=1 → negative)

Two's-complement: signed = unsigned − 2¹⁶ = 63552 − 65536 = −1984
Or: flip all bits + 1 → 0x07BF + 1 = 0x07C0 = 1984, then negate → −1984 ✓

Step 3: Scale to physical units

accel_g = −1984 / 16384 = −0.121 g (16384 LSB/g = 2¹⁵ / 2 g at ±2 g full-scale range)
accel_m_s2 = −0.121 · 9.81 = −1.19 m/s² (slight negative X tilt)

In C

int16_t raw = (int16_t)((buf[0] << 8) | buf[1]);  // cast to int16 = sign-extend
float g = raw / 16384.0f;                          // scale per datasheet
float a_ms2 = g * 9.80665f;                        // SI units

Common bug: uint16_t raw = ... then implicit promotion to int treats it as unsigned 63,552, giving accel ≈ +3.88 g. Always cast to int16_t first if the source is a signed register.

COMMON PITFALLS

  • signed overflow — +127+1 wraps to −128, not 128.
  • unsigned overflow — 255+1 wraps to 0, no error flag.
  • MSB ambiguity — 0xFF is +255 or −1 depending on type.
