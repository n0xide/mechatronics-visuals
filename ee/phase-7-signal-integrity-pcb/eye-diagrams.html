Eye Diagrams — overlaying bit periods to see what your signal looks like

Take a long bit sequence on a high-speed serial bus, overlay all bit periods on a scope (or in software), and you get an "eye" — a shape that reveals everything wrong with the channel: ISI (inter-symbol interference) closing it horizontally, jitter shaking the edges, amplitude noise closing it vertically. The eye height and width set how much margin you have before bit errors. This visual builds the eye step by step, lets you sweep channel parameters, and overlays the named standard masks (USB 3.0, PCIe Gen3, DDR4, etc.).

The math behind the eye

UI (unit interval): T_UI = 1 / bitrate Channel attenuation at Nyquist (f = 1/(2·T_UI)): A_total = loss_per_inch · length (FR-4: ~0.4-0.7 dB/in @ 2.5 GHz; low-loss laminates 0.1-0.2) V_RX = V_TX · 10^(−A_total/20) Eye height (vertical opening at center of UI): H = V_RX − 2·σ_noise (gaussian noise on each rail) Eye width (horizontal opening at decision threshold): W = T_UI − 2·σ_jitter (teaching simplification — treats RJ as a deterministic 2σ envelope. Real spec compliance at BER 10⁻¹² uses ~14·σ_RJ + DJ_pp; this visual leaves DJ aside and uses 2σ to keep the picture readable.) BER from eye margins (assuming gaussian noise): BER ≈ ½ · erfc(H / (2·σ_noise · √2)) (per-rail; multiply by 2 for both rails) Equivalently: Q = V_margin / σ_noise; BER = Q-function(Q) Bathtub curve: BER plotted vs sampling phase across the UI. Floor = minimum BER (sample at the center); walls = jitter-dominated rise as you slide off-center. Equalization gain: CTLE peaking adds ≈ +8 dB at Nyquist (typical), partially restoring lost amplitude. DFE subtracts post-cursor ISI from prior bits, adding another 6-10 dB of effective margin.

Worked example — USB 3.0 SuperSpeed on a 6-inch FR-4 trace

Setup

5 Gbps USB 3.0 (Gen 1), 6-inch differential trace on standard FR-4, 90 Ω differential impedance. What's the eye look like at the receiver?

Numbers

UI = 1 / 5 Gbps = 200 ps FR-4 loss at 2.5 GHz (Nyquist): ≈ 0.4 dB/inch → 2.4 dB over 6 inches USB 3 TX min swing: 800 mVpp diff (±400 mV per rail) After 2.4 dB loss: 800 · 10^(−2.4/20) = 800 · 0.759 = 606 mVpp USB 3 RX min mask: ±100 mV → 200 mVpp Margin = 606 − 200 = 406 mVpp (PASS with comfortable room)

If the trace gets longer

At 12 inches: 4.8 dB loss → VRX = 460 mVpp; still passes, but ISI starts closing the eye vertically. Add CTLE peaking at 2.5 GHz to flatten channel response — bumps effective amplitude back to ~580 mV.

At 24 inches: 9.6 dB loss → VRX = 264 mVpp raw. Requires CTLE + DFE at RX. This is standard in USB 3 PHY chips (TI TUSB1310A, Pericom PI3DPX series).

USB 3.0 spec budgets 12 dB end-to-end loss; with redrivers / retimers, traces up to ~40 inches work.

How to read the bathtub curve

Anatomy

  • Floor: the minimum BER you can achieve, sampling at the geometric center of the eye. Determined by vertical noise σ.
  • Walls: as you slide the sample point off-center, you cross jittered edges, BER rises steeply.
  • Horizontal margin (at BER target): distance between the BER=target intersections — this is the "open" eye width you actually have at the target BER.
  • Half-period rule of thumb: a well-designed link has horizontal margin ≥ 0.4 UI at BER = 10−12.

Measuring eye in the lab

  • Mask test on a scope — modern scopes (Keysight, Tek, R&S) have built-in eye-mask analysis. Trigger on clock, accumulate many UIs, check whether any sample falls inside the mask polygon. Pass = zero violations after N samples (typically N ≥ 109 for 10−9 BER confidence).
  • BERTscope / J-BERT — dedicated bit-error tester sweeps decision threshold + sample time, builds the actual bathtub curve. Reveals true horizontal + vertical margin.
  • SDR-based — for slower links (≤ 1 Gbps), an oscilloscope or even SDR captures the waveform; correlate offline to build the eye.
  • Embedded eye monitor — PCIe Gen 4+ SerDes blocks expose a per-lane internal eye monitor; query at runtime to track health over temperature / aging.

Common pitfalls

  • Forgetting the connector launch — 1-2 dB lost just at the connector pad geometry. Include it in the budget.
  • Eye looks fine but link fails — random jitter is gaussian (long tails). Eye looks open at 104 UIs but fails at 1012. Trust the bathtub curve, not visual eye-density.
  • Wrong reference plane — measuring at the chip pin vs the breakout via vs the trace mid-point gives different eyes. Always specify the reference plane.
  • Ignoring DJ — duty-cycle distortion and data-dependent jitter can be the dominant horizontal-closure mechanism, not RJ. Capture both.
  • Assuming linear channels — at very high data rates (25 Gbps+) the channel + receiver are nonlinear (CTLE saturation, slicer). Use simulation tools (HFSS / ADS / IBIS-AMI), not back-of-envelope.
  • Not running pre-emphasis at minimum — TX EQ is configurable but if you don't enable it, the channel sees raw edges. Always start at ≥ 3 dB emphasis on long links.
