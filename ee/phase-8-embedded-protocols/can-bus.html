CAN Bus & CAN-FD

Differential serial bus designed for automotive and industrial: every node can transmit; arbitration is non-destructive (lower ID = higher priority); two 120 Ω termination resistors at the bus ends; classical CAN runs up to 1 Mbps with 8-byte payloads; CAN-FD extends payload to 64 bytes and data-phase up to 8 Mbps (ISO 11898-1:2015 spec; most deployments cap at 2–5 Mbps for signal-integrity margin). The protocol's killer feature: a hardware-level wired-AND voting where a transmitter sending a recessive bit sees a dominant bit on the bus and yields automatically.

Arbitration — the killer feature

Every bit a transmitter sends is monitored bit-by-bit on the bus. CAN uses dominant-recessive levels: a dominant bit (0) drives the bus actively; a recessive bit (1) is the default idle state. If two transmitters send simultaneously and one sends a dominant bit while another sends recessive, the dominant wins — and the transmitter sending the recessive bit detects it and immediately drops out (without re-trying for now, just waiting for end-of-frame).

  • Lower ID = higher priority. ID 0x000 always wins arbitration.
  • Non-destructive arbitration. The winning frame transmits as if there was no collision.
  • Once arbitration is over (last bit of ID + RTR), the data phase follows. The winner has the bus.
  • Bit stuffing: after 5 consecutive same-value bits, the transmitter inserts one bit of the opposite polarity (a "stuff bit"). Receiver detects the run, removes the inserted bit, and continues. Guarantees an edge at least every 6 bit-times so the receiver PLL stays locked. EOF and IFS fields are NOT stuffed.

Bit timing

Each bit is divided into multiple "time quanta" (Tq). Receiver samples the bus at the "sample point" within each bit. Typical config: SYNC_SEG (1 Tq), PROP_SEG (1-8 Tq), PHASE_SEG1 (1-8 Tq), sample point, PHASE_SEG2 (1-8 Tq). Sample point at 75-87% of bit time is standard.

Maximum bus length is governed by the round-trip propagation time: the dominant bit a transmitter puts on the bus must reach the farthest node and be sampled (and, for arbitration, returned) within one bit time. Signal speed in twisted-pair cable is ~200 m/µs. CAN-FD differences

  • Higher data-phase rate — arbitration phase still classical rate (1 Mbps typical), data phase up to 8 Mbps per ISO 11898-1:2015 (most production buses cap 2–5 Mbps for signal-integrity margin). After arbitration is won, transmitter can switch to fast phase.
  • Larger payload — up to 64 bytes vs 8 bytes for standard CAN.
  • BRS bit — Bit Rate Switch indicates the frame is FD. CAN classic nodes will see an error.
  • 17-bit CRC for ≤16 byte, 21-bit CRC for >16 byte — stronger error detection for larger payloads.

Pitfalls

  • Missing termination — bus reflects, errors everywhere. Always 120 Ω at both ends.
  • Wrong terminator location — only at the ends, not at stubs. T-junction with short stubs is OK; long stubs cause reflections.
  • Mixed CAN / CAN-FD nodes — non-FD nodes see FD frames as errors. Use ISO 11898-1 compliant frames so even non-FD nodes can pass them through error-free.
  • Same ID on two nodes — both think they own the bus, both try to transmit. Result: bit-monitoring error and bus-off.
  • Transceiver-without-isolation in noisy environments — common-mode noise causes errors. Use isolated transceivers (ISO1050) when bus crosses ground domains.

Worked example — automotive 500 kbps CAN with body controllers

The setup

Modern car body bus: 500 kbps, 4-meter run, 8 ECUs (door modules, BCM, instrument cluster, telematics, etc.). What does each frame look like and how much bandwidth do you have?

Per-frame numbers

Bit time: 1/500e3 = 2 µs
Standard CAN frame with 8 data bytes: SOF(1) + ID(11) + RTR(1) + IDE(1) + r0(1) + DLC(4) + Data(64) + CRC(15) + CRC-delim(1) + ACK-slot(1) + ACK-delim(1) + EOF(7) + IFS(3) = 111 bits raw
Plus ~20% bit-stuffing overhead worst case → 133 bits
Frame airtime: 133 × 2 µs = 266 µs
Max frames/sec at 100% bus utilization: 1e6 / 266 ≈ 3760
Useful data: 3760 × 8 bytes = 30 kB/sec, or 240 kbps net throughput from 500 kbps raw

Practical bus loading

Industry rule of thumb: stay below 60–70 % bus load to keep worst-case latency bounded. At 500 kbps × 70 % = 350 kbps effective, you can run ~1300 frames/sec (1 frame every 750 µs average). Allocate:

  • High-priority (steering, brakes, engine): low ID 0x000–0x0FF, fast cycle (10 ms = 100/sec)
  • Medium-priority (lights, HVAC, doors): ID 0x100–0x4FF, 100 ms cycle
  • Low-priority (diagnostics, telematics): ID 0x500+, on-demand or 1 s cycle

Why CAN-FD?

Same 500 kbps arbitration phase, but data phase at 2 Mbps and up to 64-byte payload. Same arbitration semantics, much higher throughput — important for ADAS sensors generating MB/sec.

CAN-FD with 64 byte payload at 2 Mbps data phase: ~333 µs per frame → 8 KB/s useful per frame
10× the throughput of classic CAN at 500 kbps. Now standard in most 2020+ vehicles.

Error states + bus-off recovery

Every CAN node maintains two error counters: Transmit Error Counter (TEC) and Receive Error Counter (REC). They increment on errors detected during transmission or reception, and decrement on successful frames.

StateConditionBehavior
Error activeTEC < 128 AND REC < 128Normal — can transmit active error frames (drives bus dominant)
Error passiveTEC ≥ 128 OR REC ≥ 128Can transmit, but must wait extra suspend time after own frame; sends passive error frames (recessive)
Bus offTEC ≥ 256Node disconnects from bus; can only re-join after 128 × 11 recessive bits seen

This auto-isolation is critical: a faulty node that's generating constant errors won't lock up the bus. It's banished and the rest of the network keeps running.

CAN physical layer — High-speed (ISO 11898-2) vs Low-speed (ISO 11898-3)

  • High-speed (HS-CAN): 125 kbps – 1 Mbps. Differential pair with 120 Ω termination at both ends. Most common.
  • Low-speed / fault-tolerant (LS-CAN): up to 125 kbps. Bus continues operating even with one wire shorted to ground or +12 V. Used for non-critical body electronics.
  • Single-wire CAN (SW-CAN): GMLAN spec, J2411. Cheap, used for door modules in some GM vehicles. Limited to 33 kbps.
  • CAN XL (CiA 610-1; folded into ISO 11898-1 / -2 updates): up to 20 Mbps data phase, 2048-byte payload. Designed for future ADAS / EV high-throughput needs.
