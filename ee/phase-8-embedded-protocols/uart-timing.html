UART Timing

No clock line means both sides must agree on baud rate. Watch a frame on the wire and see how a ±2.5% drift accumulates across 10 bit cells before the receiver samples the wrong one.

UART is the oldest serial protocol still on every MCU. It is asynchronous: transmitter just starts shouting bits at the agreed-upon rate, receiver oversamples (typically 16×) to find the falling start-bit edge, then samples each bit cell at its midpoint. If clocks drift enough, the midpoint moves off the bit; that's a framing error.

Baud tolerance ±2.5%

The receiver locks on the start-bit falling edge, then samples every bit at the middle of the bit cell using its own clock. If the receiver clock is N% fast or slow, the sample point drifts by N% of a bit per bit. With ±2.5% tolerance and 10 bits per frame, drift can reach ~25% — still inside the bit cell. Beyond ±4–5%, the stop bit gets misread.

What to notice

  • Start bit is the sync — TTL UART line idles HIGH (mark, logical 1); the start bit is LOW (space, logical 0) for one bit-time, producing a falling edge that tells the receiver "begin sampling". No clock wire is shared, so this edge is the only sync per byte. (RS-232 inverts the voltage but the protocol-level logic is identical: idle = mark = "1", start = space = "0".)
  • LSB first — UART transmits bit 0 (least significant) first, after the start bit. ASCII 'A' = 0x41 = 0100 0001 binary. Bit 0 = 1 (LSB) goes first, then bit 1 = 0, bit 2 = 0, … bit 7 = 0 (MSB). On the wire: 1, 0, 0, 0, 0, 0, 1, 0.
  • Bit time = 1/baud — at 9600 baud, one bit cell is ~104 µs; at 115200, ~8.7 µs. The receiver samples at the midpoint.
  • ±2.5% spec, ~5% practical — the receiver re-syncs every frame on the start bit, so error only needs to stay within half a bit by the end of frame (~10 bits). Cheap RC oscillators on AVRs can fail this; that's why crystal-clocked devices are more reliable.
  • RS-232 is not TTL — same protocol, different voltages and polarity (RS-232 inverts: idle is negative). Wiring a TTL pin straight to an RS-232 port damages both sides.

Cheat sheet

MEMORIZE

  • Frame — 1 start + 8 data (LSB-first) + opt. parity + 1 or 2 stop.
  • Idle — line HIGH; falling edge = start.
  • Rates — 9600 / 115200 / 1M / 3M baud.
  • Tolerance — ±2.5% baud both sides.

WIRING DECISION

  • CROSS TX↔RX — TX of A → RX of B, RX of A ← TX of B.
  • GND must be shared — single-ended needs reference.
  • Null-modem — cable that swaps TX/RX for DTE↔DTE.

COMMON PITFALLS

  • Voltage mismatch — TTL 3.3/5 V ≠ RS-232 ±5–15 V; never mix without MAX232 or USB-UART bridge.
  • RS-232 polarity inverted — idle is negative.
  • RC oscillator drift — cheap MCUs miss ±2.5% over temp; use crystal.
