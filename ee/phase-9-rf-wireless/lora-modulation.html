LoRa — Chirp Spread Spectrum

Each symbol is a frequency that sweeps linearly across the band. SF and BW trade range vs. data rate. The math is just exponents.

LoRa modulates data into chirps — sinusoids whose frequency ramps linearly from f_c − BW/2 to f_c + BW/2 over one symbol period. The data is encoded in the starting frequency: each symbol carries SF bits, so there are 2^SF possible starting points within the band. Higher SF means more chips per symbol → more processing gain → better sensitivity, but a longer symbol time. Wider BW means faster data rate, but worse sensitivity (more noise gets in). The receiver de-chirps by mixing with a known down-chirp; this turns the spread signal into a narrow tone whose frequency reveals the data symbol.

Each SF step = ~2.5 dB extra link budget and ~2× the airtime. Each BW doubling = +3 dB more noise floor (worse sensitivity) but 2× more bits/sec.

What to notice

  • Time-on-air explodes with SF — SF7 sends 20 bytes in 56 ms; SF12 takes 1.6 seconds. LoRaWAN's 1% duty cycle in EU868 lets you transmit only 36 sec/hour total, so SF12 nodes get ~22 packets per hour max.
  • Processing gain comes from spreading — 2^SF chips per symbol means the receiver integrates over 2^SF time slots. Coherent integration gives +10·log10(2^SF) dB SNR improvement → that's why SF12 can decode signals below the noise floor.
  • Wider BW = faster but deafer — doubling BW lets in twice the thermal noise (+3 dB). So 500 kHz is 6 dB worse sensitivity than 125 kHz at the same SF. The trade-off is data rate.
  • The chirp is orthogonal to interference — narrow-band interferers (FM, BLE collision, etc.) only corrupt a tiny slice of each chirp. The dechirper averages them out. CSS is famously robust against same-band CW interferers.
  • Range estimates are LOS only — real-world urban range with SF12 is more like 3–5 km because of buildings and noise floor. The 20 km figure is for clear line-of-sight or balloon-to-ground links.

Worked example — 915 MHz LoRa sensor uplink to gateway 5 km away

The setup

Battery-powered soil-moisture sensor sends 12-byte payload every 15 minutes. Gateway is 5 km LOS (small valley). Pick SF, BW, output power, and verify link budget.

Link budget

FSPL at 915 MHz, 5 km: 32.44 + 20·log(5) + 20·log(915) = 32.44 + 14 + 59.2 = 105.6 dB
TX power (FCC US ISM max): +14 dBm
TX antenna: 2 dBi monopole; RX antenna: 5 dBi at gateway
RX signal at gateway: +14 + 2 + 5 − 105.6 = −84.6 dBm
Required RX sensitivity for SF10 at 125 kHz BW: −132 dBm
Link margin: −84.6 − (−132) = 47 dB margin ✓ — even SF7 would work LOS

Pick SF based on duty cycle + battery

SF7: ToA ≈ 56 ms · ~10 mA active · 56 ms = 0.6 µAh per packet
96 packets/day → ~58 µAh active per day
Add sleep current (~5 µA × 24h = 120 µAh/day) → total ~180 µAh/day
2× AA battery (~2500 mAh): 2,500,000 / 180 = 13,800 days = 38 years (limited by sleep, not LoRa)
Realistic: 5-10 years with self-discharge and corrosion. SF7 was the right choice — go fast, sleep deep.

Defensive design

Real conditions degrade the link: rain, foliage, body proximity, neighboring 915 MHz traffic. Bump to SF9 (4× ToA but +8 dB sensitivity) for robustness. Battery life drops from 38 y to 28 y theoretical — still way more than the sensor's other components last.

MEMORIZE

  • SF7…SF12 — each +1 step = +6 dB sensitivity AND 2× ToA.
  • BW — 125 / 250 / 500 kHz (wider = faster, deafer).
  • CR — 4/5 … 4/8 (forward error correction overhead).
  • SF12 @ 125 kHz — ≈ −137 dBm sensitivity.

COMMON PITFALLS

  • EU868 1% duty cycle — only 36 s/hr airtime per node.
  • SF12 burn rate — 20-byte payload @ 125 kHz ≈ 1.8 s; you get ~20 packets/hr.
  • SF mismatch — gateway must demod the same SF as the node, else miss.
