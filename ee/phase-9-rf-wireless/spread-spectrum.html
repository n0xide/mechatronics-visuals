Spread Spectrum — DSSS & FHSS

Two strategies to push narrowband data over a much wider bandwidth: DSSS (Direct-Sequence Spread Spectrum) multiplies the bit stream by a fast pseudo-random "chipping" code, smearing the signal across the whole channel; FHSS (Frequency-Hopping Spread Spectrum) jumps between many narrow channels in a known pattern. Both buy processing gain at the cost of bandwidth. Common in CDMA cell (DSSS), legacy WiFi (DSSS), Bluetooth Classic (FHSS), and LoRa (CSS, a related technique).

DSSS — multiply data by a chipping code

The data bit bk is multiplied by a pseudo-random chipping sequence cn that changes much faster (typically 10–1000× faster). Each data bit becomes N "chips". The receiver multiplies the received signal by the same sequence and integrates, recovering the data.

Data: bk at rate 1/T_b Chip sequence: cn ∈ {−1, +1} at rate 1/T_c (T_c < T_b) Transmitted: x(t) = bk · cn at the chip rate Receiver: y(t) · cn = bk · cn² = bk   (since cn² = 1) Spread factor SF = T_b / T_c = chipping_rate / data_rate Processing gain Gp = 10·log₁₀(SF)  dB

Because the receiver knows the sequence, the data despreads back to baseband. Any signal not multiplied by the same sequence (interference, noise) stays spread — and after the receiver's narrowband filter, only 1/SF of that interference's energy gets through.

FHSS — hop carriers in a known pattern

Instead of spreading per-bit, transmit on one narrow channel for a brief "dwell" time, then jump to a different channel. The hop pattern is a pseudo-random sequence known to both transmitter and receiver.

  • Slow FHSS: many bits per hop (Bluetooth Classic dwells 625 µs at each hop = ~50 bits).
  • Fast FHSS: more than one hop per bit (military jam-resistant).
  • Resistant to narrowband interference — a jammer at a single frequency only hits 1/N hops, recovered by FEC.
  • Bluetooth Classic: 79 channels at 1 MHz spacing in 2.4 GHz; 1600 hops/sec; hop pattern derived from device address + clock.

Processing gain in action

With SF = 100, the transmitted signal is 100× wider in bandwidth. After despreading, the receiver only "sees" interference falling into 1/100 of the bandwidth — a 20 dB rejection.

Example: data 1 kbps, spread to 100 kHz bandwidth (SF = 100). In-air SNR: receiver sees signal 20 dB below noise floor (−20 dB SNR pre-despread). After despreading: signal SNR rises 20 dB → 0 dB. If BPSK needs 10 dB SNR for BER 10⁻⁵ → you can demodulate at −10 dB SNR in air. This is why CDMA and GPS can work below thermal noise floor.

Worked example — GPS L1 C/A code (DSSS in action)

The setup

GPS satellites broadcast on L1 (1575.42 MHz) at ~50 W EIRP. By the time the signal reaches Earth's surface (20 200 km away), it's about −130 dBm — far below thermal noise. Yet a $5 GPS module decodes it. How? Pure processing gain.

The numbers

Data rate: 50 bps (the 1500-bit navigation message)
Chip rate: 1.023 Mchips/s (the C/A pseudorandom code)
Spread factor: 1.023e6 / 50 = 20460
Processing gain: 10·log(20460) = 43 dB
Thermal noise floor (1 MHz BW): −174 + 60 + 5 (NF) = −109 dBm
SNR in air: −130 − (−109) = −21 dB (signal 21 dB below noise!)
SNR after despread: −21 + 43 = +22 dB (clean signal!)

Why it works

The receiver knows each satellite's C/A code. It generates the same pseudorandom sequence locally, time-shifts it to match the received signal (correlation peak detection), then multiplies. Signal × its own code → concentrates back to 50 Hz bandwidth (coherent). Noise × different sequence → stays spread across 1 MHz. After the receiver's narrowband filter, ~99.99 % of the noise is rejected. 43 dB processing gain is why GPS works at all.

Code families — how multiple users coexist

Different users (or satellites) get different pseudorandom codes chosen so their cross-correlation is approximately zero — they are orthogonal. Multiple users can transmit on the same frequency at the same time, and each receiver despreads only its own user's signal.

Common pitfalls

  • Synchronization is the hardest part. The receiver must align its local code to within a fraction of a chip period. GPS solves this with a correlator bank — try 1023 code shifts at 2× chip rate = 2046 hypothesis tests per satellite.
  • Doppler shifts the chip clock — a satellite moving at 4 km/s changes the chip rate by 4 km/s × 1.023 MHz/c = 13.6 Hz. The despreader must search frequency AND code phase.
  • Near-far problem in CDMA — a nearby strong user can mask a distant weak user's signal because Walsh orthogonality breaks down under power imbalance. Cell-phone CDMA uses tight power control (~1000× per second) to keep all users at the receiver at equal power.
  • FHSS follower jammers — a smart jammer that detects the hop and follows it within microseconds can defeat slow-hop FHSS. Fast-hop FHSS (faster than the jammer's reaction time) restores immunity.
  • LoRa Doppler at high speed — chirp spread spectrum is sensitive to Doppler at vehicle speeds. Use lower spreading factor (SF7-SF9) for moving applications, SF10-SF12 for fixed.

Cheat sheet

FORMULAS

  • SF = chipping_rate / data_rate
  • G_p = 10·log₁₀(SF) dB
  • Required pre-SNR = post-SNR − G_p
  • Bandwidth = data_rate × SF (DSSS)

WHEN TO USE

  • DSSS: multiple users in same band (CDMA), long range with low SNR (GPS)
  • FHSS: rapid jammer-resistant comms, regulatory (FCC ISM)
  • CSS (LoRa): long range + low power for IoT

PITFALLS

  • Code length too short → poor processing gain
  • Cross-correlation between codes → multi-user interference
  • FHSS hop too slow → vulnerable to follower jamming
  • Doppler shift in CSS → de-chirp offset
