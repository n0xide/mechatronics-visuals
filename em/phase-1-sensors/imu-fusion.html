IMU Sensor Fusion — combining accel + gyro + mag into stable orientation

A single IMU axis can't tell you orientation. Accelerometer gives gravity (slow, low-noise tilt) but is corrupted by linear acceleration. Gyroscope gives instantaneous angular rate (fast, drifts) but integrates the bias error into unbounded angle drift. Magnetometer gives heading (slow, distorted by ferrous metal). Sensor fusion combines them, getting each one's strengths and rejecting each one's weaknesses. This visual simulates a 1-axis IMU walking through a 10-second trajectory with realistic sensor noise + bias, and runs three fusion algorithms in parallel: raw gyro integration (drifts), complementary filter (cheap), and Mahony PI filter (a-step-up).

The three estimators side-by-side

Raw gyro integration (worst baseline): θ_gyro[k+1] = θ_gyro[k] + ω_meas · Δt Drift = (bias + noise mean) · t → unbounded Accel-only (high-pass through linear-accel noise): θ_accel = atan2(ax, az) (1-axis tilt model) Bounded but noisy + corrupted whenever sensor accelerates linearly Complementary filter (low-pass accel + high-pass gyro): θ[k+1] = α · (θ[k] + ω · Δt) + (1 − α) · θ_accel α = τ / (τ + Δt); τ = filter time constant (typ 0.5-2 s) Trusts gyro at high freq, accel at low freq; cheap (3 mul + 1 add per sample) Mahony PI filter (better when bias is non-zero): Cross-product error: e = a_meas × a_predicted (a_predicted = R·[0,0,1]) ω_corrected = ω_meas + K_p · e + K_i · ∫e dt Quaternion update: q[k+1] = q[k] + ½ · q[k] ⊗ [0, ω_corrected] · Δt Madgwick (a more aggressive grad-descent variant): Same data, but step direction chosen by gradient of an objective function Slightly faster convergence + less compute (no integral state)

The complementary-filter math in detail

The complementary filter works because gyro and accel have complementary noise spectra: gyro is good at high frequencies (it's integrated, so DC bias drifts), accel is good at low frequencies (gravity is DC, but vibration adds high-freq noise). A simple first-order low-pass on accel + high-pass on gyro, summed, recovers the true angle.

In discrete time: θ[k] = α · (θ[k−1] + ω_meas · Δt) + (1 − α) · θ_accel Choose α = τ / (τ + Δt): Δt = sample period (e.g., 10 ms) τ = time constant (e.g., 1 s) ⇒ α = 1 / 1.01 = 0.990 High α (≈ 1) trusts gyro: smooth, fast response, but bias drifts in slowly Low α (e.g., 0.9) trusts accel: noisy from vibration, but bias-free Sweet spot: 0.95-0.99 for typical drone / robot applications

Pros: 5 ops per sample, embedded-friendly, intuitive tuning.
Cons: assumes static accel = gravity (false during fast motion); doesn't model bias explicitly.

Worked example — drone roll-axis fusion

Setup

250-class racing drone, MPU6050 IMU at 1 kHz update. Gyro bias post-calibration: ±0.3 °/s. Accel noise: 5 mg RMS. Sample period Δt = 1 ms.

Choose τ

Pick τ = 0.5 s (typical for drone) → α = 0.5 / 0.501 = 0.998 High-pass corner: 1/(2π·τ) = 0.32 Hz — anything below this is dominated by accel Steady-state residual angle from constant gyro bias = bias · τ = 0.3 °/s · 0.5 s = 0.15°. The complementary filter saturates this offset — it does not integrate forever — because the accel correction term cancels the bias-driven drift in steady state. During a 0.5 s 90°/s yaw maneuver: tracking error < 1° (gyro-dominated, no accel correction)

If using Mahony instead

K_p = 1.0, K_i = 0.05 (typical published values) Steady-state integrator state (bias compensation magnitude): ε_ss = ω_bias / K_i = 0.3/0.05 = 6 °·s (integrator-state units, since K_i has units of s⁻² and ω_bias is in °/s) — that's the level the I-term parks at to null out the constant bias, not a residual angle error or a rate. Convergence ~1 s. After convergence: drift < 0.05° per minute (bias explicitly tracked) CPU cost: ~30 multiplies per sample at 1 kHz = 30k MAC/s — trivial for STM32 F4

Common pitfalls

  • Sample timing jitter — fusion assumes Δt is constant. If your sensor read is in a low-priority task that gets preempted, Δt varies, and integrated angle drifts even more. Use DMA + timer-triggered sampling.
  • Forgetting accel-corruption during motion — α=0.98 is fine when stationary; during a hard turn, the centripetal accel masquerades as tilt, and the filter rotates the estimate the wrong way. Gate the accel update: skip it when |a| not ≈ 1 g.
  • Mag interference — motor currents, batteries, and steel frame all distort the field. Calibrate after mounting (not on the bench) and verify with a "spin test" rotating the device.
  • Quaternion normalization — every update, ‖q‖ drifts from 1.0 due to floating-point. Re-normalize each cycle: q /= ‖q‖.
  • Gimbal lock — Euler-angle (roll/pitch/yaw) representation singular at pitch = ±90°. Use quaternions internally, convert to Euler only for human display.
  • Initial-condition convergence — Mahony/Madgwick converge from any initial quaternion, but slowly. Initialize from a 0.5-1 s static average of accel to start near the true tilt.
  • Temperature drift on gyro bias — re-zero bias at startup (assume device stationary) and ideally during use (when angular rate is below noise floor). MEMS gyros drift ~0.5 °/s per °C.
  • Different sample rates — accel often 50-200 Hz, gyro 1 kHz, mag 50 Hz, GPS 10 Hz. Fusion runs at gyro rate; other sensors update when fresh data arrives. Need a state flag per sensor.
