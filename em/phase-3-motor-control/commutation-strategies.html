Commutation Strategies — Trapezoidal vs Sinusoidal vs FOC

A 3-phase BLDC has three windings that must be energized in the right sequence to spin the rotor. There are three increasingly sophisticated ways to do this: 6-step trapezoidal (simple), sinusoidal (smoother), and Field-Oriented Control / FOC (smoothest, most efficient, most complex). This visual walks the progression — what each gives you, what it costs, and when to pick which.

The three strategies — how they differ

1. Trapezoidal (6-step block commutation)

Energize 2 of 3 windings at a time. The current path through the motor stays the same for 60° of electrical rotation, then jumps to the next 2-winding combination. Six discrete states (sectors) per electrical revolution. Need to know which sector you're in — either Hall sensors (3 of them) or BEMF zero-cross detection (sensorless).

Pros + cons

+ Simple. Runs on Cortex-M0 with no FPU. Cheap. Hall sensors widely available. Sensorless BEMF detection works on outrunner motors at modest speeds.

− Torque ripple ~14 % (peaks each commutation). Audible cogging at low speed. Difficult to operate at very low speed (no BEMF for sensorless).

Use for: hobby drones, fans, simple pumps, low-cost appliances. Anywhere where smoothness isn't critical.

2. Sinusoidal commutation

Instead of 6 discrete states, apply continuous 3-phase sinusoidal voltages with 120° phase shifts. The motor sees smoothly rotating stator field with no abrupt commutation jumps. Requires accurate rotor position (encoder, not just Hall) so the sinusoid is correctly aligned.

V_A = V_peak · sin(θ_elec) V_B = V_peak · sin(θ_elec − 120°) V_C = V_peak · sin(θ_elec − 240°) θ_elec = pole_pairs · θ_mechanical PWM modulates each phase's average voltage to match the sinusoid.

Pros + cons

+ Smooth torque (ripple ~4 %). Quieter motor. Better at low speed than trapezoidal sensorless.

− Requires encoder for accurate alignment. Compute slightly higher than trap (need to compute sin × 3 phases at PWM rate). Doesn't decouple flux from torque — still inefficient at high speed.

Use for: HVAC fans, dishwasher pumps, mid-grade industrial automation. Used widely in the 2000s before FOC became cheap.

3. Field-Oriented Control (FOC)

The Park transform rotates the stator current vector into the rotor's reference frame: the d-axis (along the rotor flux) and q-axis (perpendicular, torque-producing). Closed loops control I_d (typically held at 0) and I_q (proportional to torque). After computation, the inverse Park transform rotates back to stator (a, b, c) coordinates for the PWM.

1. Measure phase currents I_a, I_b, I_c (Kirchhoff: I_a + I_b + I_c = 0) 2. Clarke: (I_a, I_b, I_c) → (I_α, I_β) — stationary 2-axis 3. Park: (I_α, I_β) → (I_d, I_q) using rotor angle θ 4. PI loops: control I_d → 0 (no flux command) and I_q → I_q_ref (torque command) 5. Output: V_d, V_q from PI controllers 6. Inverse Park: (V_d, V_q) → (V_α, V_β) 7. SVPWM: (V_α, V_β) → 3-phase PWM duty cycles 8. Apply to gate drivers → MOSFETs → motor

Pros + cons

+ Torque ripple < 1 %. Maximum efficiency (decoupled flux + torque means correct current for any speed). Field-weakening above base speed extends speed range. Industry standard for premium servos, EVs, robotics.

− Compute-heavy (multiplies + sin/cos + 2 PI loops at 10–20 kHz). Needs encoder for rotor angle (or sensorless observer like SMO / EKF). Tuning is harder — current loops bandwidth ~kHz, position loop bandwidth ~100 Hz.

Use for: robotics (every modern joint controller), e-bikes, e-scooters, EV drivetrains, drone gimbals, industrial servos.

Worked example — picking strategy for a robot joint

The use case

6-DOF robot arm joint. Motor: 100 W BLDC, 1500 RPM rated, 14 pole-pairs. Encoder: 4096 counts/rev absolute. Update rate: 1 kHz position loop, 20 kHz current loop. MCU: STM32G474 (Cortex-M4F @ 170 MHz).

Why FOC

  • Robot joints need to hold position smoothly at zero speed — only FOC delivers (trap cogs visibly).
  • The 1500 RPM × 14 pole-pairs = 350 Hz electrical fundamental. Both sinusoidal and FOC can handle this at 20 kHz PWM (57 PWM cycles per electrical cycle).
  • The encoder is already there for the position loop — using it for FOC is free.
  • STM32G474 has an FPU and runs FOC inner loops in < 10 µs of its 50 µs PWM period. Plenty of margin for position loop, comms, safety.
  • FOC's decoupled flux + torque means you can scale to high torque without efficiency loss. Trap loses efficiency at low speed / high torque.

Why NOT FOC (the alternative)

If the motor was driving a propeller (drone): trap is fine. Torque ripple averages out over the prop's inertia. The 6-step approach is simpler, fewer compute cycles, lower latency. Use a Cortex-M0 if cost matters.

Common pitfalls

  • Trap commutation tied to wrong sector — phase order or Hall mapping wrong. Motor judders or runs backward. Always verify open-loop spin first.
  • Sinusoidal without encoder calibration — sinusoid alignment is off by some offset; torque is suboptimal. Calibrate by parking the rotor at a known electrical angle (apply DC to one phase) and recording encoder count.
  • FOC current loop bandwidth too high — drives saturation in PWM duty; current chatters. Set bandwidth ~ω_PWM / 10.
  • FOC d-axis current not zero — wastes copper losses (heat) for no torque. Always check I_d output of current PI; it should be small at steady state.
  • Sample point wrong in FOC — current ADC must sample at PWM midpoint (when switching is quiet). Misaligned → noisy current readings → poor torque.
  • Sensorless BEMF at low speed — BEMF is proportional to speed; below ~5 % rated speed it's lost in noise. Use a startup ramp (I-f or HFI) until BEMF is reliable.

Code sketch — FOC inner loop in C

void foc_inner_loop(void) {
    // 1. Read currents (synchronized to PWM midpoint via ADC trigger)
    float ia = adc_to_amps(adc.ch_a);
    float ib = adc_to_amps(adc.ch_b);
    float ic = -(ia + ib);  // Kirchhoff

    // 2. Read encoder, compute electrical angle
    float theta_mech = encoder_read_rad();
    float theta_elec = theta_mech * POLE_PAIRS;
    float c = cosf(theta_elec);
    float s = sinf(theta_elec);

    // 3. Clarke (a,b,c) -> (alpha, beta)
    float i_alpha = ia;
    float i_beta  = (ia + 2.0f*ib) * (1.0f / SQRT3);

    // 4. Park (alpha,beta) -> (d, q) with rotor angle
    float i_d =  c * i_alpha + s * i_beta;
    float i_q = -s * i_alpha + c * i_beta;

    // 5. PI controllers (current loop, bandwidth ~ kHz)
    float v_d = pi_update(&pi_d, 0.0f      - i_d);  // I_d ref = 0
    float v_q = pi_update(&pi_q, iq_ref    - i_q);  // I_q ref from position loop

    // 6. Voltage saturation, anti-windup
    // SVPWM max |V_dq| = V_BUS/sqrt(3) ~= 0.577*V_BUS. Use 0.9 of that as safety.
    saturate_voltage(&v_d, &v_q, V_BUS * 0.577f * 0.9f);

    // 7. Inverse Park (d, q) -> (alpha, beta)
    float v_alpha = c * v_d - s * v_q;
    float v_beta  = s * v_d + c * v_q;

    // 8. SVPWM: (alpha, beta) -> 3 duty cycles
    svpwm_set(v_alpha, v_beta);
}

Field-weakening (FOC bonus)

Above base speed, back-EMF saturates available bus voltage. FOC can weaken the rotor flux by injecting negative I_d. This reduces effective back-EMF, allowing higher speeds at lower torque. The motor's speed-torque envelope extends 2–3×.

Catch: weakening also reduces maximum torque available. Trade-off: high-speed low-torque region (e.g., cruise on a Tesla). Critical for EVs and high-speed BLDC.
