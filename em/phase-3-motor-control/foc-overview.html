FOC — Field-Oriented Control

Transform the 3-phase AC current into two DC numbers that live in the rotor's reference frame. Then PID them. Then transform back.

FOC is what makes a BLDC behave like a brushed DC motor with infinite life — torque proportional to a single scalar (i_q), commanded by a simple PI loop. The trick is coordinate transformation: starting from three measured phase currents (i_a, i_b, i_c) that are sinusoidal in the stator frame, apply Clarke to collapse to two orthogonal stationary axes (i_α, i_β), then Park (using the measured rotor angle θ) to land in a frame that rotates with the rotor. In that frame the formerly-spinning current vector stands still, decomposed into i_d (along the magnet flux, sets reluctance/field-weakening) and i_q (perpendicular, sets torque). Two PI loops regulate these to setpoints; inverse Park + SVPWM converts the PI outputs back into three phase voltages for the half-bridges. Under the hood it's just a rotated PID — but rotating it into the right frame is the entire game.

What to notice

  • i_d sets flux (or weakens it), i_q sets torque — for surface-PM motors (most BLDC), commanded i_d* = 0 because there's no reluctance torque to harvest. All your current produces torque via i_q. For interior-PM (IPM) motors and field-weakening above base speed, drive i_d* < 0 to fight magnet flux.
  • Outer loop wraps inner — position loop outputs velocity setpoint → velocity loop outputs torque (= i_q*) setpoint → current loop outputs voltages. Rule of thumb: each loop runs 5–10× faster than the one it feeds. Inner current loop at 10–20 kHz, velocity at 1–2 kHz, position at 100–500 Hz.
  • Encoder accuracy = FOC quality — Park transform uses θ to rotate the frame. If θ is off by 10° elec, your "torque current" leaks into "flux current," efficiency drops, torque ripples. Magnetic encoders (AS5048A) at 14-bit give ~0.022° — plenty. Halls alone (60° resolution) are too coarse — FOC with halls is a degraded mode.
  • Need only two phase currents — Kirchhoff: i_a + i_b + i_c = 0, so measure two, compute the third. Saves a shunt & an ADC channel.
  • SVPWM ≈ sinusoidal + 3rd harmonic injection — geometrically it's "which space-vector pair is closest, and how long do I spend on each in this PWM period." Practically: get 15% more usable voltage than naive sine modulation. STM32 HAL implements it natively.
  • Current-loop tuning starts from L & R — set PI bandwidth ~ω_BW; K_p = L·ω_BW, K_i = R·ω_BW. Tune for ~1–2 kHz BW first, then verify with a step response. Outer loops follow with bode-spacing.

Cheat sheet

TRANSFORMS

Clarke
i_α = i_a i_β = (i_a + 2·i_b)/√3
Park
i_d = i_α·cos θ + i_β·sin θ i_q = −i_α·sin θ + i_β·cos θ
Torque
T = (3/2)·P·λ_PM·i_q
P = pole pairs, λ_PM = magnet flux linkage
PI tune
K_p = L·ω_BW · K_i = R·ω_BW

STACK (ARM PROJECT)

  • MCU — STM32G431 (FPU + HRTIM + fast ADC).
  • Driver — DRV8316 / TMC6300 / B-G431B-ESC1 dev board.
  • Encoder — AS5048A (SPI, 14-bit magnetic).
  • Library — SimpleFOC (Arduino-ish) or motorcontrol-stm32 HAL.
  • PWM — 20 kHz center-aligned, ADC trig mid-period.
  • Loop rates — current 10 kHz, vel 1 kHz, pos 250 Hz.

COMMON PITFALLS

  • θ offset wrong — align: command i_d* > 0, rotor will snap to θ=0; record encoder reading as offset.
  • Current sample timing off — must sample mid PWM, not at edges; jitter trashes the loop.
  • Pole-pair count wrong — affects θ_elec = θ_mech · P; off by 2× → motor spins wrong way or not at all.
  • Encoder direction inverted — flip sign of θ in code or swap any two phases.
  • PI windup — clamp integrator when output saturates at V_dc.
  • Forgetting field weakening above base speed — back-EMF saturates V_dc, torque collapses; inject i_d* < 0.
