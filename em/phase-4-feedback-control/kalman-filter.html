Kalman filter — predict, then update

A Kalman filter fuses two noisy estimates of the same quantity — one from a process model (prediction), one from a sensor (measurement) — into a single estimate that is more confident than either input. The math reduces to weighting by inverse variance, then iterating. This visual shows the Gaussian-merge intuition and a full 1-D tracking simulation against truth.

Gaussian fusion — the geometric intuition

The prior (blue) represents what the model believes about the state right now. The likelihood (orange) represents what the sensor just measured. The posterior (green) is the product of the two Gaussians, normalised — always sharper than either input. The Kalman gain K is just the ratio that says how far to move from prior toward measurement.

The two-step cycle

StepPredictUpdate
OperationAdvance state estimate using modelCorrect estimate with new measurement
State eq.x̂_k|k-1 = A·x̂_{k-1} + B·u_{k-1}x̂_k = x̂_k|k-1 + K·(z_k − H·x̂_k|k-1)
CovarianceP_k|k-1 = A·P_{k-1}·Aᵀ + QP_k = (I − K·H)·P_k|k-1
Gain—K = P_k|k-1·Hᵀ · (H·P_k|k-1·Hᵀ + R)⁻¹
EffectUncertainty (P) growsUncertainty shrinks

What to notice

  • The posterior is always narrower than either input. That's the magic: fusion always gains information. Two noisy estimates of the same quantity are more confident together than apart.
  • Kalman gain K balances trust. When sensor variance R is small, K → 1 and the filter trusts the measurement (jumps to it). When R is large, K → 0 and the filter sticks with its model prediction. Slide R from low to high to feel this.
  • Q is your trust in the model. If Q is small, the filter believes the model strongly — smooth output, but slow to react to true changes. Crank Q up and the filter chases every measurement.
  • The complementary filter is a fixed-gain Kalman. α·model + (1−α)·measurement, with α hand-tuned. Cheap, fast, no covariance bookkeeping. Used everywhere in IMU fusion when proper Kalman is overkill.
  • EKF for nonlinear systems. Linearise around the current state estimate every step using Jacobians. The math is the same; the linearisation is the assumption. Falls over if nonlinearity is severe — UKF or particle filter then.
  • The filter is recursive. No history needed beyond the current state + covariance. Tiny memory footprint, runs on microcontrollers. The reason Apollo could land on the Moon with a 64 KiB computer.

Cheat sheet

1-D KALMAN (SCALAR)

Predict
x̂_pri = x̂_{k-1} + u·dt
P_pri = P_{k-1} + Q
Gain
K = P_pri / (P_pri + R)
Update
x̂_k = x̂_pri + K·(z − x̂_pri)
P_k = (1 − K)·P_pri

WHAT THE KNOBS DO

  • Q small → trusts model → smooth but laggy
  • R small → trusts sensor → jittery but responsive
  • P auto-adjusts; you tune Q and R only
  • Complementary filter x = α·model + (1−α)·meas; α ≈ 1 − K_∞ (fixed-gain Kalman)
  • EKF — replace A, H with Jacobians ∂f/∂x, ∂h/∂x

PITFALLS

  • Wrong R (sensor variance miscalibrated) — filter trusts the wrong source
  • Wrong Q — filter diverges from truth or is too sluggish to react
  • Non-Gaussian noise (sun glints, outliers) — basic Kalman is fooled; use robust variants
  • Severe nonlinearity — EKF linearisation breaks; consider UKF or particle filter
  • Unobservable state — filter never converges (revisit observability matrix)
