Reset & Brownout

Microcontrollers don't tolerate ambiguous power. They expect to power up cleanly through a defined sequence (power-on reset, POR), and to be held safely in reset when the supply dips below the brown-out threshold (BOR). When you skip one of these, you get the "occasionally hangs at boot" bug that defies all logic. This visual covers POR/BOR thresholds, RC reset delays, external supervisor ICs, and what a real brown-out event looks like on the scope.

Power-on reset (POR)

At power-up, V_DD rises from 0 V to the operating range over some non-zero time. Before V_DD reaches a defined minimum, the CPU's flip-flops are in an unpredictable state — neither 0 nor 1, and not robust against noise. If you let the CPU start executing in this state, anything can happen: corrupted PC, wrong vector address, garbage register values.

Every modern MCU has built-in POR logic: when V_DD crosses a defined threshold (V_POR, usually ~0.7–1.5 V), it asserts an internal reset signal and starts a startup timer. Only when V_DD is stable above operating minimum AND the timer expires does reset release.

Brown-out reset (BOR)

BOR is a separate guard: after the chip is happily running, if V_DD drops below a programmable threshold (V_BOR), the BOR circuit pulls reset back low. The chip stops executing until V_DD recovers.

Without BOR, a brief supply dip leaves the chip in an indeterminate state: flash-write operations might be half-completed (corrupting code), the CPU may hang in a fault, or the program runs from a wrong PC and crashes the system.

RC reset delay — the simplest "supervisor"

Some MCUs (older 8-bit and some FPGAs) need an external reset pulse after V_DD stabilizes. The standard trick: an RC network on the !RESET pin. Power comes up; capacitor charges through R; voltage on !RESET rises slowly; when it crosses the Schmitt-trigger threshold (~0.7 V_DD), the chip leaves reset.

Reset delay τ = R · C Time to cross 0.7 V_DD ≈ 1.2 · τ Typical: R = 10 kΩ, C = 100 nF → τ = 1 ms → reset releases after ~1.2 ms For slow supplies that take longer to settle, use τ = 10 ms (R = 100 kΩ, C = 100 nF) or even 100 ms.

RC alone has a problem: it only delays the initial reset. If V_DD dips later, the RC doesn't help — the cap is already charged. That's why an external supervisor IC is much better than a bare RC for any system that might experience brown-outs.

External supervisor IC

A supervisor IC is a tiny three-pin chip with a precise voltage reference and comparator. Examples: TI TPS3823, Microchip MCP101, ON Semi NCP301. It watches V_DD and pulls its open-drain RESET output low whenever V_DD < V_threshold.

Why use one in addition to internal BOR?

  • More accurate threshold — supervisors are ±1.5 % typical; internal BOR is often ±5–10 %.
  • Programmable threshold — pick exactly the V_BOR you need (e.g., 3.08 V for a 3.3 V system, with 6 % headroom for noise).
  • Manual reset input — many supervisors include a !MR input for a reset button.
  • Power-up timing — fixed 200 ms typical reset-active delay after V_DD passes threshold, gives the supply time to settle.
  • Watchdog — some supervisors (e.g., MAX6816) include a watchdog timer that resets the chip if the MCU doesn't tickle it.

Brown-out scenario — what happens without BOR

t=0: System running normally at 3.3 V. t=10 ms: A 5A motor pulls in, supply rail dips to 2.0 V for 5 ms. No BOR: CPU executes from a flaky supply. Possible outcomes: - CPU latches up; only power-cycle recovers. - A flash-write in progress is aborted; the page contains garbage. - PC corrupts; CPU jumps to an unknown address. - RAM contents corrupt (often subtly; the chip "works" but state machines are broken). With BOR @ 2.4 V: chip enters reset at 2.4 V. Stays reset until V_DD ≥ 2.4 V again. Reboots clean. → The cost of BOR is one fuse setting; the cost of not having it is hours of debugging "random crashes."

What to notice

  • Enable BOR by default. Most STM32s ship with BOR disabled to save 3 µA in deep sleep. For any battery-powered or motor-driven board, that's a false economy.
  • Threshold above V_min, below V_normal. If V_DD = 3.3 V nominal and chip min = 1.8 V, set V_BOR around 2.7 V. Below normal regulation; above absolute min; with enough margin that supply ripple doesn't trigger spurious resets.
  • External supervisor for stuff that matters. Anything that does flash-writes, motor control, or talks to an SD card: budget $0.25 for a supervisor IC. It pays for itself the first time you avoid a power-glitch bug.
  • RC reset is for hobby projects and FPGAs. It's a power-up delay, not a brown-out detector. Don't confuse the two.
  • Schmitt trigger on reset — both internal and supervisor logic include hysteresis (typically 50–100 mV) to prevent oscillating on the edge of the threshold.

Where you'll see this

Real uses

  • Motor-driven systems — inrush dips the supply; BOR is mandatory.
  • USB-powered boards — host disconnect during write causes brown-out; supervisor prevents flash corruption.
  • Battery-operated devices — cell discharge curve crosses V_BOR before V_DD is too low for safe execution.
  • SD-card loggers — write-in-progress brown-out can leave the FAT in a corrupted state. BOR + journaled FS = essential.
  • FPGAs — usually require external supervisor; internal POR is too lenient.

RULES OF THUMB

  • Enable BOR on every board you ship. Default-on if possible.
  • RC reset C = 100 nF, R = 10 kΩ for ~1 ms.
  • External supervisor for any flash-write/SD/motor system.
  • BOR-reset reason is usually logged in RCC->CSR — read at boot.
  • Combine with watchdog for full fault coverage.

COMMON PITFALLS

  • BOR disabled by default on many STM32. Easy to miss.
  • RC charged before chip ready — slow supplies need bigger τ.
  • Reset pin not pulled up — open-drain supervisor floats high.
  • Flash-write during dip — even with BOR, a write in progress at the trigger instant may corrupt one sector.
  • Hot-swap brown-outs — adding a power-hungry peripheral mid-run; supervisor catches what BOR misses.
