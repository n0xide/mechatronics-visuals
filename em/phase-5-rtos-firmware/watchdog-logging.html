Watchdog & Deterministic Logging

Two boring topics that save the system. The watchdog catches firmware that locks up; the log ring buffer lets you trace what happened without blocking the control loop.

A watchdog timer (WDT) is a hardware countdown that resets the MCU if firmware fails to "kick" (refresh) it within a configured timeout. It exists because firmware can hang — infinite loop, deadlock on a mutex, stack overflow, brown-out partial corruption. Without a WDT, a hung MCU sits there forever, drone fell out of the sky, arm slumped against the table. With one, the MCU resets in ≤1 s, runs its init, and you may not even notice. Independent watchdogs (STM32 IWDG, RP2350 WATCHDOG) run from a separate oscillator so they survive even if the main clock dies. Window watchdogs add an "earliest" bound — if you kick too soon, also reset. Catches runaway loops that happen to kick at the wrong rate.

The matching topic: deterministic logging. printf blocks on UART (115200 baud = ~870 µs per byte). One printf("loop %d\n", i) in a 10 kHz current loop adds milliseconds and trashes deadlines. The right pattern is a ring buffer in RAM: the producer (any task or ISR) writes a fixed-size record to the next slot in O(1); a low-priority drain task or DMA channel ships the bytes out the UART at its own pace. If the producer outruns the drain, oldest entries get overwritten — log loss, not deadline miss. Critical-path code stays predictable.

Wrong — printf in control loop

void control_loop(void) {
  for(;;) {
    sample = read_adc();
    pid_update(sample);
    write_pwm(out);
    printf("err=%.2f\n", err);   // ~5 ms blocking
    vTaskDelayUntil(&t, 1);          // "1 kHz" → ~200 Hz
  }
}

Loop drops from 1 kHz to 200 Hz the moment logging is enabled. Bench tests pass without logging.

Right — ring buffer + DMA drain

// In control loop (fast path):
log_event(EVT_PID, sample, err);     // ~50 cyc, lockless

// log_event:
uint32_t i = atomic_fetch_add(&wr_idx, 1) & MASK;
ring[i] = (rec_t){tag, a, b, tick};  // 16 B write

// Drain task (LOW priority):
while(rd_idx != wr_idx) {
  HAL_UART_Transmit_DMA(&huart, &ring[rd_idx], 16);
  rd_idx = (rd_idx + 1) & MASK;
}

Control loop overhead is constant 50 cycles. DMA controller does UART without CPU.

What to notice

  • Run the watchdog sim — green run, kicks land before timeout. At "fault injected," firmware stops kicking. Watchdog counts down to zero, resets the MCU. The system recovers automatically; user sees a glitch, not a permanent hang.
  • Kick interval < timeout — with safety margin. Rule of thumb: kick at ~⅓ of timeout. If your worst-case loop is 100 ms, set timeout to 300 ms and kick every 100 ms.
  • Watchdog from a low-priority task — if you kick from a fast ISR, the watchdog never catches priority inversion or task starvation. Put the kick at LOWEST priority — it only runs when every higher-priority task has yielded. Best of both: dedicated watchdog task that collects heartbeats from all RT tasks via counters.
  • printf is the assassin of real time — at 115200 baud, sending 20 bytes is 1.7 ms of blocking UART. In a 10 kHz loop (100 µs budget) that's 17 missed deadlines per call. Use ring buffers everywhere.
  • Lockless ring buffers — single-producer/single-consumer rings need no mutex if read/write indices are atomic and the buffer size is a power of 2 (mask cheaper than mod). Look up SPSC vs MPMC.
  • Log when the buffer overflows — when producer outruns drain, increment a "lost" counter. Don't silently overwrite. The lost count tells you logging is undersized.

BUGS THAT BITE

  • Kicking from a high-priority ISR — defeats the watchdog. It can't catch starvation of the very loop you care about.
  • Disabling watchdog "for debug" — and forgetting to re-enable for flight.
  • printf in any RT path — including ISRs (also illegal there).
  • Ring buffer size not power of 2 — modulo becomes a divide; way more cycles.
  • Logging from ISR + task simultaneously — MPMC needed; SPSC will corrupt. Use FreeRTOS message buffer or atomic queue.
  • UART RX without DMA — burst data → overrun, lost bytes silently.
