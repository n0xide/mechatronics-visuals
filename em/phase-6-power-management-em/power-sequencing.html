Power Sequencing on Boot

Which rail comes up first? Analog before digital, core before I/O, supervisor before MCU release. Brown-out, slow-start, POR. Regime: multi-rail power-up transient and brown-out events, first ~hundred milliseconds. Steady-state architecture is on the rail-architecture page.

Multi-rail systems can't all turn on at once. If the MCU comes up before its analog reference is stable, the first ADC reads are garbage. If a 3.3 V I/O rail comes up before the 1.2 V core, the I/O pads can forward-bias the I/O-to-core protection structures and latchup is possible on some processes. If the MCU's RESET line releases before the 3.3 V supply has settled within its operating tolerance (typically ±5−10 %), code starts executing on rails outside the part's guaranteed-operating window. Power sequencing is the contract between rails: the order they ramp, how long after each other, and who tells the MCU it's safe to start.

What to notice

  • Core before I/O. The 1.2 V core has to come up before the 3.3 V I/O pads, or the I/O pads pull current through the I/O-to-core protection diodes — latchup risk on some processes. Most modern SoCs have a tolerance window (a few hundred mV), but the design rule is "core first."
  • RESET is the last signal to release. Even if all rails are up, the MCU must be held in reset until everything is stable. A supervisor IC (or the supervisor inside a PMIC) watches all rails; only when every monitored rail is in spec does it release the active-low RESET pin.
  • Brown-out detector catches dips during operation, not just boot. If V_in sags below the BOR threshold mid-flight (e.g., motor inrush pulls the bus down), the BOR re-asserts RESET. This is a feature, not a fault — better to reset than to execute on collapsing rails.
  • Slow-start ramps the inrush. A 1000 µF bulk cap on a 5 V rail charges instantly if you slam the converter on — peak current is limited only by the inductor. Soft-start (an RC on the enable pin, or built into the converter) ramps V_out over 1−10 ms, capping I_inrush to ~C·dV/dt.
  • Concurrent enable is risky but common. If you tie all the EN pins together, rails come up roughly together — usually OK if all converters have built-in soft-start and the MCU's POR window is wide. The "broken" mode here shows what happens when 3.3 V wins the race against 1.2 V.
  • The supervisor delay is not optional. Even after rails are nominally in spec, the MCU needs time for PLL lock, flash readout, and bootloader handoff. 50−200 ms of "stable" before RESET release is standard.

SEQ RULES

  • Core before I/O — or coincident within tolerance.
  • Analog after digital settles — let switching transients pass.
  • RESET released last, after supervisor sees all rails good.
  • Power-down: reverse order, or all-at-once if shut down is unrecoverable anyway.
  • Soft-start on every rail with >100 µF bulk.

COMMON PITFALLS

  • No supervisor, MCU starts on dirty rails — sporadic boot fails on cold start.
  • Capacitor inrush trips fuse — 5 A fuse, 2200 µF cap, no soft-start → nuisance blow.
  • BOR set too low — MCU runs on collapsing rail before BOR catches it; corrupt EEPROM writes.
  • BOR set too high — can't operate at low end of battery range; cuts runtime.
  • Wrong power-down order — analog ref collapses, MCU writes garbage flash on power-fail.
