Bench Bring-up Procedure

Each stage gates the next. Never jump ahead — a hidden bug from step 2 ruins step 5 in ways you'll spend a weekend debugging. Click a step to expand its checklist.

Bring-up is the moment a new joint board moves from "the schematic + PCB are done" to "it can spin a motor under closed-loop control." It is a sequence — not a checklist — because each step proves a layer of the stack before you put load on the next. The fastest path to "it works" is paradoxically the most patient one: prove power before comms, comms before sensors, sensors before actuation, open-loop before closed-loop. Skipping ahead is how you let the magic smoke out. The pattern below works for any embedded subsystem, but is shown here for a joint controller (STM32 + DRV8316 + BLDC + AS5048A).

What to notice

  • The order is non-negotiable — you cannot diagnose a current-loop instability while still doubting whether your encoder reads right. Resolve uncertainty bottom-up.
  • Gates between steps — a "gate" is the one observable that proves the previous step. If the gate fails, you stop. Trying to make the next step work without passing the gate just compounds failures.
  • Smoke test is real — first power-on, no firmware, current-limited PSU at 0.1 A. If something draws unexpectedly, you've caught a short before it cooked. Cost: 30 seconds. Benefit: every time it saves you, the board.
  • Open-loop before closed-loop — applying a fixed PWM duty and watching the rotor jerk-step is how you confirm phase order. Closed-loop fails silently when phase order is wrong; open-loop tells you immediately.
  • Each loop tier tested independently — current loop with a stationary rotor first, velocity loop with no position outer, position loop only after velocity tracks. Tuning N loops simultaneously is impossible.
  • Bring-up is bidirectional — when something breaks in production, the same procedure runs in reverse: is the position loop bad? Disable it, test velocity. Bad? Disable it, test current. Etc. Bring-up procedure = diagnostic procedure.

When a step fails

Do not skip ahead. The arm-6dof-pa612 spec sheet has each gate's expected scope/multimeter reading; deviations indicate the specific failure mode. Logbook every reading — when production units fail later, the bench-baseline is the comparison.

Cheat sheet

BENCH KIT

  • Current-limited PSU — set 0.1 A first, ramp up only after smoke test.
  • JTAG/SWD debugger — ST-LINK V3 or J-Link mini (with SWO for ITM).
  • Multimeter — measure rails before powering MCU.
  • Oscilloscope — for PWM waveforms, phase voltages.
  • Logic analyzer — Saleae or DSLogic for SPI/CAN/UART decode.
  • USB-CAN dongle — to sniff messages without the host.

RULES OF THUMB

Smoke test
I_limit = 100 mA; if drawn → short.
Encoder check
Rotate by hand, log raw counts, expect monotonic.
Phase order
Open-loop sinusoid; rotor follows = correct.
Current loop BW
Start at 500 Hz, raise to 1–2 kHz once stable.
Velocity loop BW
5–10× slower than current loop.
Position loop BW
5–10× slower than velocity loop.

COMMON PITFALLS

  • Powering on with full V_bat — always start current-limited. Future you will thank present you.
  • Skipping the comms test — if CAN doesn't enumerate on the bus, you'll never debug a motor problem through it.
  • Trusting an unaligned encoder — every new motor + encoder pairing needs a zero-offset calibration before FOC will work.
  • Closing position loop while velocity loop oscillates — the position loop will look unstable but the bug is one tier down.
  • No bench fixture — a spinning motor under closed loop will yeet itself off the bench. Clamp the housing.
  • One-step debugging — change one thing per test cycle. Otherwise you can't attribute the result.
