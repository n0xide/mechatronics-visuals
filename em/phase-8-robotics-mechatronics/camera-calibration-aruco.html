Camera Calibration & ArUco Pose

A pinhole camera turns 3D points into pixel coordinates via a 3×3 intrinsic matrix K and a 4-parameter distortion model. Once you've calibrated K, you can do the reverse: a known-size marker (like an ArUco fiducial) gives four 2D-to-3D correspondences, and solvePnP returns the marker's 6-DOF pose relative to the camera. This is the foundation of every webcam-based AR demo and every cheap vision-guided robot.

The pinhole camera model

A point P = (X, Y, Z) in 3D camera-frame coordinates projects to a pixel (u, v) via two steps:

Step 1 — normalize by depth: x_n = X/Z, y_n = Y/Z (these are the "ideal" coordinates of where the ray hits a plane at Z = 1). Step 2 — apply the intrinsic matrix K: u = f_x · x_n + c_x v = f_y · y_n + c_y Compactly, in homogeneous coordinates: [u·s, v·s, s]ᵀ = K · [X, Y, Z]ᵀ

The intrinsic matrix K

The K matrix is 3×3:

K =  ┌ f_x   0   c_x ┐
     │  0   f_y  c_y │
     └  0    0    1  ┘
  • f_x, f_y: focal lengths in pixels. f_x = (sensor focal length in mm) × (pixels per mm in x-direction). Usually f_x ≈ f_y unless the sensor is non-square or the lens has anamorphic features.
  • c_x, c_y: principal point — where the optical axis hits the sensor, in pixel coords. Usually within a few pixels of the image center; never assume exactly center without calibrating.
  • Skew (the 0 above f_y): usually 0 for digital sensors. For chip-on-prism beamsplitter cameras or analog systems it can be nonzero.

Distortion — k1, k2, p1, p2

Real lenses don't project ideal rays. Brown-Conrady model captures most of the deviation with four (or five) coefficients:

Radial: r² = x_n² + y_n² x_n' = x_n · (1 + k1·r² + k2·r⁴) + 2·p1·x_n·y_n + p2·(r² + 2x_n²) y_n' = y_n · (1 + k1·r² + k2·r⁴) + p1·(r² + 2y_n²) + 2·p2·x_n·y_n k1 alone captures the dominant "barrel" or "pincushion" distortion. k1 > 0 = pincushion; k1 < 0 = barrel (fisheye look). k2 cleans up residuals at the corners. p1, p2 capture tangential distortion (lens not perfectly aligned with sensor plane). Wide-angle lenses (GoPro, action cams) need a more complex model: equidistant, equisolid-angle, or polynomial-of-higher-order.

ArUco markers — what they are

An ArUco marker is a black-and-white square with an inner pattern that encodes an integer ID. The OpenCV ArUco module includes pre-generated dictionaries: DICT_4X4_50 (4×4 grid of bits, 50 unique IDs), DICT_5X5_100, DICT_6X6_250, etc.

The detection pipeline:

  1. Convert image to grayscale, adaptive threshold.
  2. Find contours; filter for quad-shaped ones of plausible size.
  3. Warp each quad to a fixed grid; sample bits.
  4. Match against the dictionary; reject if > N bits in error.
  5. Refine corners with subpixel methods.

The marker is a known size in the world (e.g., 50 mm × 50 mm printed on paper). Detecting its four corners in the image gives four 2D-to-3D correspondences:

Object point (marker frame)Image point (pixel)
(−s/2, −s/2, 0)(u_TL, v_TL)
(+s/2, −s/2, 0)(u_TR, v_TR)
(+s/2, +s/2, 0)(u_BR, v_BR)
(−s/2, +s/2, 0)(u_BL, v_BL)

solvePnP — pose from 4+ correspondences

Given 4+ 2D-3D correspondences and known intrinsics K, the perspective-n-point (PnP) problem returns:

  • rvec — Rodrigues rotation vector (3-element axis-angle). Convert to 3×3 R matrix via Rodrigues formula.
  • tvec — translation (3-element x, y, z in marker units, e.g., mm).

Together, R and t form the 4×4 SE(3) transformation from marker frame to camera frame. To get the inverse (camera in marker frame, for fixed-marker robot localization): T_marker_to_cam → T_cam_to_marker = (T)⁻¹.

OpenCV's cv2.solvePnP() has several methods: SOLVEPNP_ITERATIVE (default, robust), SOLVEPNP_AP3P (closed-form, very fast), SOLVEPNP_EPNP (works with many points). For 4-corner ArUco at 30 fps, SOLVEPNP_IPPE_SQUARE is specifically designed for planar quads and is the fastest correct choice.

Worked example — pose-estimate a 50 mm marker

The camera

Raspberry Pi Camera Module 3 (1080p mode): f_x ≈ f_y ≈ 1380 px, c_x ≈ 960, c_y ≈ 540 (image is 1920 × 1080). k1 ≈ -0.12, k2 ≈ 0.05 (slight barrel distortion). FOV ≈ 70° horizontal.

The marker

ArUco from DICT_4X4_100, ID 7, printed at 50 mm size on cardstock, glued to a robot arm tool tip.

Detection result

OpenCV detects the marker; corners refined; subpixel accuracy ~0.1 px. Object points: (±25, ±25, 0). Image points: detected.

PnP solve

solvePnP returns rvec = [0.052, -0.014, 1.523] rad, tvec = [12, -8, 487] mm. Converting rvec via Rodrigues gives a 3×3 R; combined with t, that's the full T_marker_in_cam.

Accuracy

Typical error for 50 mm marker at 500 mm distance with refined corners: ±2 mm translation, ±1° rotation. Closer or bigger marker → better. Lighting and motion blur are the biggest enemies. Use ChArUco boards (a chessboard with ArUco in the white squares) for more robust pose at the cost of larger size.

What to notice

  • f_x is in pixels, not mm. Beginners confuse focal length in mm (lens spec) with f_x in pixels (calibration result). Conversion: f_x_px = f_mm / pixel_pitch_mm.
  • Calibration with a chessboard is the standard workflow. Show the camera a printed chessboard from 15+ angles; OpenCV's calibrateCamera() fits K and distortion.
  • Distortion matters for pose accuracy. Even k1 = 0.1 (mild barrel) skews a marker's corners by several pixels at the edges. PnP gets confused; pose has 5–10 mm errors. Always undistort or pass the distortion coefficients to PnP.
  • Smaller markers at far distances are noisier because fewer pixels span the marker. Rule of thumb: marker should be at least 40 × 40 pixels for reliable pose. At 50 mm marker, f=1000, that means Z ≤ 1.25 m.
  • Multiple markers reduce ambiguity. A single planar marker has a "flip" ambiguity (Z-axis can flip 180°) when viewed near-perpendicular. ChArUco or AprilTag-3 (with embedded code) resolves this; or use 2+ markers in a known rigid arrangement.

Where you'll see this

Real uses

  • Vision-guided robot arms — pick objects whose pose is read from an ArUco marker glued to them.
  • Drone delivery localization — ArUco markers on landing pads or houses.
  • VR controller tracking (early Oculus / WMR) — infrared LEDs in known constellation, same math.
  • Augmented reality apps — Vuforia, ARCore, ARKit all use markers + SLAM under the hood.
  • 3D-scanner ground truth — fiducial markers placed on object define a consistent reference frame.

RULES OF THUMB

  • Calibrate with 15+ chessboard views at varied angles.
  • f_x ≈ image_width / (2·tan(FOV/2)).
  • ArUco corners ≥ 40 px each for reliable PnP.
  • Use IPPE_SQUARE for planar 4-corner PnP.
  • Two markers resolve flip ambiguity.

COMMON PITFALLS

  • Wrong focal length units — px vs mm confusion.
  • Skipping distortion — corners pulled outward, pose drifts.
  • Marker bend / paper warp — assumed planar, actually curved.
  • Motion blur — corners noisy; pose jitters.
  • Wrong dictionary — detector returns nothing.
