Denavit-Hartenberg parameters

Four numbers per joint (a, α, d, θ) describe any serial-chain robot arm. Each row builds a single 4×4 homogeneous transform T_{i-1}^{i}. Multiplying them base-to-tool gives the entire forward kinematics. This visual lets you edit the table directly and watch a 3D-projected arm reshape.

The DH row in one formula

Each row builds: T = Rot_z(θ) · Trans_z(d) · Trans_x(a) · Rot_x(α). Expanded:

[ cosθ -sinθ·cosα sinθ·sinα a·cosθ ] [ sinθ cosθ·cosα -cosθ·sinα a·sinθ ] [ 0 sinα cosα d ] [ 0 0 0 1 ]

This is the "standard" (distal) DH convention. There's also a "modified" (Craig / proximal) convention used in some textbooks where the rotation is applied first; pick one and stick with it. URDF doesn't use a DH convention at all — it specifies each parent→child transform explicitly with XYZ + RPY and a joint axis, so you must convert between DH and URDF by hand when interoperating with DH-based tooling (Robotics Toolbox, MoveIt SRDF analysis, etc.).

What to notice

  • α (twist) is the angle between successive joint axes. α = 0 → both axes parallel (planar arm). α = 90° → perpendicular (typical between shoulder and elbow on an anthropomorphic arm).
  • a (link length) is the common perpendicular between axes. Not the same as the visual "length of the link" you might draw — it's a geometric distance along the x-axis after the rotation.
  • θ is the only variable for a revolute joint. The other three (a, α, d) are constants from the mechanical design. For a prismatic joint, swap: d is the variable, θ is the constant.
  • The base→tool transform's translation column is the tool position (x, y, z) — exactly what FK computes. The 3×3 rotation block is the tool orientation.
  • Changing one θ ripples through every downstream link. The matrix product is non-commutative: order matters. Swap two rows and you get a different robot.
  • URDF + tf2 hides this from you. When you publish joint states in ROS 2, tf2 internally builds and chains these transforms. Knowing DH lets you debug "why is my tool frame off by a constant" — usually a wrong α or d.

Cheat sheet

THE 4 DH PARAMETERS

a
link length — common perpendicular dist. between axis i and i+1
α
link twist — angle between consecutive axes about common perp
d
link offset — dist. along axis i between common perpendiculars
θ
joint angle — rotation about axis i (variable for revolute)

BUILDING A DH TABLE

  • Step 1 — assign z-axes along each joint motion axis.
  • Step 2 — locate x-axis perpendicular to z_{i-1} and z_i.
  • Step 3 — measure a, α, d, θ from the geometry.
  • Step 4 — fill one row per joint, including base→1 if needed.
  • Sanity check — plug zero joints; tool should be at "home" pose.

PITFALLS

  • Standard vs modified DH — different multiplication order. Don't mix conventions in one project.
  • α only takes 0, ±90°, 180° on most industrial arms — geometry is designed for clean kinematics. Weird α values usually mean you assigned frames wrong.
  • Tool offset — DH ends at the wrist; add a final tool transform for end-effector / TCP.
  • URDF is convention-agnostic, not modified-DH — it stores per-joint XYZ + RPY origins directly. Use tf2 echo as ground truth and convert by hand if you need DH for another tool.
