Path Planning — A* vs RRT vs RRT*

Three of the canonical motion-planning algorithms, each with a different sweet spot. A* is the king of grid search: optimal on discrete grids, fast with a good heuristic. RRT (Rapidly-exploring Random Tree) handles continuous spaces and high-DOF arms but isn't guaranteed optimal. RRT* rewires the tree to improve toward optimality as more samples accrue. A* — informed graph search

A* explores nodes in a grid (or graph), always expanding the node with the lowest f(n) = g(n) + h(n), where g is cost-from-start and h is an estimate of cost-to-goal (the heuristic).

Manhattan heuristic (4-connected grid): h = |Δx| + |Δy| Euclidean (any direction): h = √(Δx² + Δy²) Chebyshev (8-connected with diagonals at cost √2): h = max(|Δx|, |Δy|)

If the heuristic is admissible (never overestimates) and consistent (triangle inequality), A* finds the optimal path. Manhattan is admissible on 4-connected grids; Euclidean is admissible everywhere. Both are consistent.

Time complexity: O(b^d) worst-case, where b is branching factor and d is path length. In practice, the heuristic prunes most of the search.

RRT — random expansion

For high-DOF problems (robot arms with 6+ joints), grids explode in memory. RRT instead samples the continuous space randomly:

Initialize tree T with just the start node. Loop: Sample a random point p_rand in the space. Find the nearest node n_near in T. Steer from n_near a short distance toward p_rand, getting p_new. If p_new is collision-free, add it to T as a child of n_near. If p_new is close to the goal, return the path. Until iteration limit reached.

RRT is probabilistically complete — given infinite samples, it will find a path if one exists. It is not optimal — the path it returns may zigzag inefficiently. But it works in dimensions where A* is intractable, like a 7-DOF arm's configuration space (a 7-dimensional hyper-volume).

RRT* — rewiring for optimality

RRT* adds two steps to RRT to converge toward the optimal path:

  • Choose parent: when adding p_new, look at all nodes within radius r; pick the one that minimizes total cost from start.
  • Rewire: also check each nearby node; if connecting it through p_new would lower its cost, rewire it as a child of p_new.

Over enough iterations, RRT* converges to the optimal path. Trade-off: each iteration is more expensive (O(log n) nearest-neighbor + radius search), and you need an admissible cost-to-go metric.

What to notice

  • A* is fast on grids when the heuristic is good. With a perfect heuristic, it expands only path nodes — linear time. With h=0 (Dijkstra), it expands everything.
  • RRT explores everywhere first — the tree blossoms outward roughly uniformly, then funnels to the goal. Good for finding any path quickly in cluttered spaces.
  • RRT* makes lousy paths better with time — early paths look like spaghetti; after a few thousand more samples, they straighten toward optimal. Use it as an anytime algorithm: stop whenever you've used the time budget.
  • Heuristic affects A* speed but not correctness. Manhattan is fine for 4-connected; Euclidean is fine everywhere. Switch to diagonal-distance (Chebyshev) on 8-connected grids.
  • Real systems mix planners: A* for the global plan on a downsampled grid, then RRT* (or DWA, MPC) for local replanning around dynamic obstacles.

Where you'll see this

Real uses

  • ROS Nav2 — Dijkstra/A* for global planner; DWB/MPPI for local; RRT* available as plugin.
  • Robot arm motion planning — MoveIt uses RRT/RRT-Connect from OMPL.
  • Self-driving car planning — hybrid A* (lattice planner) with kinematic constraints.
  • Drone autonomy — RRT* for 3D obstacle avoidance.
  • Video-game AI — A* is the universal pathfinder in NPCs.

RULES OF THUMB

  • A* on 2D grid: Manhattan or octile heuristic.
  • RRT step size: 1–5 % of map diagonal.
  • RRT goal bias: 5–10 % (sample directly at goal).
  • RRT* radius r: γ·(log n / n)^(1/d) (Karaman-Frazzoli).
  • Smooth the output: path-shortening + B-spline for robot motion.

COMMON PITFALLS

  • Non-admissible heuristic — A* returns suboptimal path silently.
  • RRT step too small — slow expansion, lots of samples.
  • RRT step too big — easily misses narrow passages.
  • Forgetting kinematic constraints — A* path through a wall corner not drivable by Ackermann robot.
  • Closed-set bugs in A* — re-visiting nodes that should be closed.
