TF tree — ROS 2 coordinate frames

In a ROS 2 robot every component has its own coordinate frame; the system needs to compute transforms between any pair on demand (camera → base, lidar → map, tool → world). The TF tree organises every frame as a parent-child tree rooted at the world. Asking for "transform from A to B" means walking up from A to the lowest common ancestor and back down to B — multiplying matrices along the way.

Static vs dynamic transforms

Static transforms are published once and never change: base_link → laser_link (laser is bolted to the chassis). Published by static_transform_publisher or from the URDF.

Dynamic transforms change with time: every revolute joint contributes one, published by robot_state_publisher reading joint_states and the URDF. SLAM publishes map → odom, odometry publishes odom → base_link.

What to notice

  • Every transform is parent → child. The reverse is computed by inverting the matrix. tf2 handles inversion automatically.
  • To get A → B, walk up from A to a common ancestor, then down to B. The tree must be acyclic; a frame can have only one parent. (You can have multiple children.)
  • Standard REP-105 frames: map (global, drifts via SLAM corrections), odom (smooth but drifts), base_link (robot body), base_footprint (ground projection), then sensor and tool frames downstream.
  • Disconnected trees = TF error. If a joint isn't being published or a static transform is missing, tf2 echo will fail. Always run ros2 run tf2_tools view_frames to dump the tree.
  • Timestamp matters. tf2 stores a buffer of recent transforms; querying at time t uses interpolation. A dropped publisher = stale transforms = "extrapolation into the future" errors.
  • For MoveIt 2: the planning scene reads tool0 → world via the joint chain. If a static transform between camera_link and base_link is wrong, the arm will reach for objects in the wrong spot.

Cheat sheet

TF MATH

Walk up
T_root←A = T_root←p₁ · T_p₁←p₂ · … · T_pn←A
A → B
T_A←B = T_A←root · T_root←B
Inverse
T_A←B = (T_B←A)⁻¹
Point transform
p_A = T_A←B · p_B
Composition
T_A←C = T_A←B · T_B←C

ROS 2 COMMANDS

  • view tree — ros2 run tf2_tools view_frames → frames.pdf
  • echo a transform — ros2 run tf2_ros tf2_echo source target
  • static publisher — static_transform_publisher x y z r p y parent child
  • robot_state_publisher — reads URDF + /joint_states → publishes joint transforms
  • rviz2 — set Fixed Frame to map (or base_link); visualise the whole tree

PITFALLS

  • Multiple parents — illegal. A frame has exactly one parent. tf2 will print a fight.
  • Disconnected subtrees — query fails with "no transform from X to Y". Check missing static publishers.
  • Stale transforms — joint publisher died → tf2 starts extrapolating. Watch /diagnostics or set buffer size.
  • Wrong fixed frame in rviz — robot appears in random orientation. Set to map or base_link consistently.
  • Camera-base calibration — the static TF from camera → base must be correct to millimetres for pick-and-place. Calibrate, don't measure.
