Dimensioning & Tolerance Stack-Up

Same bar with four features. Three ways to dimension it. Click any dimension to see the tolerance chain it feeds into. Move the slider to set the per-dimension ± value and watch worst-case sum diverge from RSS — and watch chain dimensioning explode while baseline dimensioning stays bounded.

What this teaches

Tolerance stack-up is why "every dim has ±0.1, what could go wrong" goes wrong. Chains add; baselines don't. Worst-case (linear sum) is the conservative bound; RSS (root-sum-square) is the statistical reality when errors are independent. Pick the dimensioning *scheme* before you pick the values.

What to notice

  • Chain accumulates. Click the last dim in scheme 1: every ± from the start of the bar piles on. With 4 segments at ±0.1, worst-case is ±0.4 mm at the far end.
  • Baseline cuts the chain. Click the same downstream feature in scheme 2: only ±0.1 applies, because each dim refers back to the single datum edge.
  • Worst-case vs. RSS. Worst-case (linear sum) assumes every error stacks in the same direction. RSS = √(Σt²) assumes errors are independent random — usually a factor of √n smaller for n stages. For 4 stages at ±0.1: worst = ±0.40, RSS ≈ ±0.20.
  • FDM caveat. RSS only fits when errors are *independent*. Printer X-axis bias is systematic — every hole drifts the same direction. For FDM, design to worst-case unless you've measured the bias and compensated.
  • Mixed scheme is the real-world answer. Tie functional features to the datum; let cosmetic spacings chain. Costs the same drawing real-estate; saves tolerance budget where it matters.
  • Reference dimensions (REF). Often the chain-style values are shown (REF) alongside baselines so a shop can sanity-check spacing without using them for tolerance.

Cheat sheet

MEMORIZE

  • Baseline dim — accumulates ONE tolerance (datum-referenced).
  • Chain dim — accumulates N tolerances (stage-by-stage).
  • REF — informational only; no tolerance budget.

STACK-UP FORMULAS

Worst case
Σ t_i = n · tall errors aligned
RSS
√(Σ t_i²) = √n · tindependent random

COMMON PITFALLS

  • Bidirectional dims — default to unidirectional; pick a single arrow convention.
  • Double-dimming — one dimension per feature, no redundancy.
  • RSS on FDM — printer bias is systematic, not random; use worst-case.
